2. Instalar Jenkins con Docker

docker run -d -p 8080:8080 -p 50000:50000 --name jenkins jenkins/jenkins:lts

Interfaz web: http://localhost:8080

docker stop jenkins
docker start jenkins

3. Primer acceso

  1. Abre http://localhost:8080
  2. Contraseña inicial: docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword
  3. Install suggested plugins
  4. Crea usuario administrador
La contraseña del archivo inicial solo se usa una vez. Después entras con el usuario del wizard.

4. Instalar Node.js en el contenedor

docker exec -u root jenkins bash -c "apt-get update -qq && apt-get install -y -qq curl ca-certificates gnupg && curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt-get install -y -qq nodejs"

6. Crear el pipeline

  1. New Item → toDo → Pipeline
  2. Pipeline script from SCM → Git
  3. URL: https://github.com/mjtamayo89/toDo.git
  4. Branch: */main
  5. Script Path: Jenkinsfile

7. Etapas del Jenkinsfile

Actualizado: el Jenkinsfile actual es una versión mínima, solo para probar que Jenkins clona el repo. No corre tests, build ni Sonar todavía.

pipeline {
    agent any
    stages {
        stage('Checkout') {
            steps { git 'https://github.com/mjtamayo89/toDo.git' }
        }
        stage('Mostrar archivos') {
            steps { sh 'ls -la' }
        }
    }
}

7.1 La versión completa sigue disponible

El pipeline completo (backend + frontend + SonarQube) quedó guardado como Jenkinsfile_v1 en la raíz del repo:

Stage (en Jenkinsfile_v1)CarpetaComando
CheckoutraízDescarga código desde GitHub

Backend: Buildbackend/mvn -B package -DskipTests
Installfrontend/npm ci
Test + Coveragefrontend/npm run test:coverage
Buildfrontend/npm run build

Para reactivarla: copia el contenido de Jenkinsfile_v1 dentro de Jenkinsfile, o cambia el Script Path del job a Jenkinsfile_v1 en Configure → Pipeline.

8. Ejecutar el pipeline

  1. Job toDo → Build Now
  2. Revisar Console Output
Con la versión mínima, un build verde solo confirma el checkout. Si activaste Jenkinsfile_v1, SonarQube debe estar corriendo en http://localhost:9000 antes de construir.

9. Flujo habitual

Con el Jenkinsfile mínimo:

Codificar → git commit → git push → Jenkins Build Now → Checkout → ls -la

Con Jenkinsfile_v1 (pipeline completo):

Codificar → git commit → git push → Jenkins Build Now → Checkout → Backend: Test → Backend: Build → Install (front) → Test + Coverage → Build (front) → SonarQube → Ver resultados en SonarQube
Jenkins solo usa el código de GitHub. Siempre haz git push antes de Build Now.

10. Solución de problemas

  • npm not found: instala Node en el contenedor (paso 4)
  • Git auth failed: repo privado sin token → hazlo público o añade credencial GitHub
  • Sonar connection refused: usa host.docker.internal:9000
  • Sonar se cierra: proceso Java colgado → cierra instancias anteriores
